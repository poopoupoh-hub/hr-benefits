# ระบบจัดการข้อมูลพนักงานและสวัสดิการ (HR Benefits)

Web app สำหรับยื่นเบิกสวัสดิการ ตรวจสิทธิ์/วงเงินอัตโนมัติ **HR ตรวจและอนุมัติ → บัญชีจ่าย** คำนวณวันจ่ายเงิน และตรวจสอบประวัติย้อนหลัง
**Next.js 16 + Tailwind CSS 4 + TypeScript · เก็บข้อมูลใน localStorage ของเบราว์เซอร์ (ไม่ต้องมีฐานข้อมูล/Backend)** · Mobile-first ตามต้นแบบ UI ในสไลด์ (กลุ่ม 43)

## เริ่มใช้งาน (2 คำสั่ง)

```bash
npm install
npm run dev        # เปิด http://localhost:3000
```

ไม่ต้องติดตั้งฐานข้อมูล ไม่ต้องตั้งค่า `.env` — เปิดครั้งแรกระบบสร้างข้อมูลตัวอย่างลง localStorage ให้อัตโนมัติ
👉 คู่มือละเอียดทีละขั้น: **[docs/GETTING-STARTED.md](docs/GETTING-STARTED.md)**

## Flow การอนุมัติ

```
 พนักงานยื่น ──▶ รอ HR ตรวจ ──HR อนุมัติ──▶ อนุมัติแล้ว รอจ่าย ──บัญชีบันทึกจ่าย──▶ จ่ายแล้ว
                  │   │
                  │   └─HR ส่งกลับ (ต้องมีเหตุผล)─▶ ส่งกลับแก้ไข ──ผู้ยื่นแก้แล้วส่งใหม่──▶ รอ HR ตรวจ
                  └─HR ไม่อนุมัติ (ต้องมีเหตุผล)─▶ ไม่อนุมัติ (คืนสิทธิ์)
```

| สถานะ | ใครเปลี่ยนได้ | ไปเป็น |
|---|---|---|
| `pending_hr` รอ HR ตรวจ | HR / หัวหน้า HR (ยกเว้นคำขอของตัวเอง) | `approved` / `rejected` / `returned` |
| `returned` ส่งกลับแก้ไข | พนักงานเจ้าของคำขอ | `pending_hr` |
| `approved` อนุมัติแล้ว รอจ่าย | บัญชี | `paid` |

- ปุ่มที่เกี่ยวกับเงินทุกปุ่ม (อนุมัติ / บันทึกการจ่าย) มีกล่องยืนยันแสดง **เลขคำขอ + ยอดเงิน**
- **แก้ผลหลังตัดสินแล้ว (Maker–Checker):** HR กด "ขอแก้ผล" → หัวหน้า HR อนุมัติจึงมีผล · หัวหน้า HR อนุมัติคำขอของตัวเองได้แต่ต้องใส่รหัสผ่านซ้ำ (บันทึก `selfApproved`) · คำขอที่จ่ายแล้วแก้ไม่ได้ · ระหว่างรอแก้ผลล็อกการจ่าย
- **แก้วงเงิน** เป็นคำขอแก้ไขเช่นกัน — อนุมัติแล้วเพิ่มวงเงินฉบับใหม่ ไม่ทับฉบับเดิม

**5 บทบาท:** พนักงาน (ยื่น/ติดตาม) · HR (ตรวจและอนุมัติ, ข้อมูลหลัก, ส่งคำขอแก้ไข) · หัวหน้า HR (HR + อนุมัติคำขอแก้ไข) · บัญชี (จ่ายเงิน, รายงาน) · ผู้ดูแลระบบ (ผู้ใช้, RBAC, Audit Log, ตั้งค่า)

**แยกหน้าที่ (ล็อกใน RBAC แก้ไม่ได้):** Admin/บัญชีอนุมัติไม่ได้ · HR จ่ายเงินไม่ได้ · ไม่มีใครพิจารณาคำขอเบิกของตัวเองได้ · Audit Log ดูได้เฉพาะผู้ดูแลระบบ

## การเก็บข้อมูล (localStorage)

| คีย์ / ที่เก็บ | เนื้อหา |
|---|---|
| `localStorage["hr-benefits:db"]` | ข้อมูลทั้งหมด (พนักงาน, สวัสดิการ, คำขอ, การจ่าย, Audit Log, อีเมล ฯลฯ) เป็น JSON ก้อนเดียว |
| `localStorage["hr-benefits:session"]` | ผู้ใช้ที่เข้าสู่ระบบ (หมดอายุ 8 ชม., เปลี่ยนรหัสผ่านแล้ว session เดิมใช้ไม่ได้) |
| IndexedDB `hr-benefits-files` | ไฟล์แนบ (แยกจากข้อมูลหลักตาม NFR, รองรับไฟล์ ≤ 5 MB) |

- ทุกคำสั่งแก้ข้อมูลเป็น transaction: แก้บนสำเนา → สำเร็จจึงเขียนลง localStorage (ล้มกลางทางไม่มีข้อมูลค้าง)
- เปิดหลายแท็บพร้อมกันได้ (เช่น แท็บ HR กับแท็บบัญชี) — อ่านค่าล่าสุดก่อนแก้ทุกครั้ง และหน้าจออัปเดตทันทีเมื่อแท็บอื่นแก้
- สำรอง/กู้คืน (JSON) และรีเซ็ตข้อมูลเดโม: ผู้ดูแลระบบ → ตั้งค่าระบบ (มีแถบแสดงพื้นที่ที่ใช้ไป)

## สถาปัตยกรรม (5 ชั้นตามสไลด์)

```
Presentation   src/app/**, src/components/**          หน้าจอ ฟอร์ม เมนูตามสิทธิ์
     │ api.<คำสั่ง>()  (src/lib/client/api.ts — จุดเดียวที่ต้องแก้ถ้าย้ายไปมี Backend)
Application    src/lib/domain/rules.ts                 กติกาบริสุทธิ์: วงเงิน 3 ระดับ, สิทธิ์, วันจ่ายเงิน, ลำดับสถานะ
Service        src/lib/services/*.ts                   workflow + RBAC (assertCan) + Maker–Checker + Audit Log + อีเมล
Data Access    src/lib/data/*.ts                       db.ts (localStorage), files.ts (IndexedDB), session.ts, scope.ts
Database       localStorage / IndexedDB ของเบราว์เซอร์
```

รายละเอียดกติกาและเรื่องที่ต้องยืนยันกับผู้ให้หัวข้อ: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)

## ขอบเขตที่ทำแล้ว (Functional Requirements)

5 บทบาท (พนักงาน / HR / หัวหน้า HR / บัญชี / ผู้ดูแลระบบ) · เข้าสู่ระบบด้วยชื่อผู้ใช้ + รหัสผ่าน · จัดการพนักงาน · แผนก / ตำแหน่ง 4 ระดับ / หัวหน้างาน · ประเภทสวัสดิการแบ่งหมวด · วงเงินตามระดับตำแหน่ง · ยื่นคำร้อง + เลขใบเสร็จ/ร้าน + แนบเอกสาร · คำนวณ "ขอเบิก → เบิกได้จริง" ทันที · เตือนใบเสร็จซ้ำ · **HR อนุมัติ / ไม่อนุมัติ / ส่งกลับ (กล่องยืนยันยอดเงิน)** · บัญชีบันทึกการจ่าย (เงินสด/โอน/เช็ค) · คำขอแก้ไขผล/วงเงินแบบ Maker–Checker (หัวหน้า HR อนุมัติ) · รอบงบภัยพิบัติ · คำนวณวันจ่าย · แจ้งเตือนอีเมล (จำลอง) · Audit Log (เฉพาะผู้ดูแลระบบ) · รายงานยอดเบิกต่อสวัสดิการ · Export CSV · สำรอง/กู้คืน

## ข้อจำกัดที่ควรรู้ (localStorage)

- **ข้อมูลอยู่ในเบราว์เซอร์เครื่องนั้นเท่านั้น** — คนละเครื่อง/คนละเบราว์เซอร์ไม่เห็นข้อมูลกัน, ล้างข้อมูลเว็บไซต์ = ข้อมูลหาย (สำรองเป็น JSON ได้)
- localStorage จำกัดราว 5 MB ต่อเว็บไซต์ (ข้อมูลตัวอย่างใช้ ~0.2 MB) — ถ้าเต็มระบบแจ้งเตือนเป็นภาษาไทยและไม่บันทึกครึ่ง ๆ กลาง ๆ
- การตรวจสิทธิ์ (RBAC) และการตัดข้อมูลตามบทบาททำในเบราว์เซอร์ จึงเหมาะกับ **เดโม/ต้นแบบ/ทดสอบ workflow** ผู้ที่เปิด DevTools อ่าน localStorage ได้ทั้งหมด — ก่อนใช้งานจริงหลายผู้ใช้ให้ย้าย service layer ไปไว้บนเซิร์ฟเวอร์ (โค้ด service/rules ใช้ต่อได้ทั้งหมด แก้เฉพาะ `src/lib/client/api.ts` และ `src/lib/data/db.ts`)
- อีเมลเป็นโหมดจำลอง (ดูได้ที่ ผู้ดูแลระบบ → อีเมลแจ้งเตือน)
- นอกขอบเขตตามสไลด์: โอนเงินอัตโนมัติ, Payroll/ภาษี, OCR ใบเสร็จ, Native app
