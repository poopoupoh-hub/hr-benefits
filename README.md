# ระบบจัดการข้อมูลพนักงานและสวัสดิการ (HR Benefits)

Web app สำหรับยื่นเบิกสวัสดิการ ตรวจสิทธิ์/วงเงินอัตโนมัติ อนุมัติตามสายงาน คำนวณวันจ่ายเงิน และตรวจสอบประวัติย้อนหลัง
**Next.js 16 + Tailwind CSS 4 + TypeScript + Prisma 7 (SQLite / PostgreSQL)** · Mobile-first ตามต้นแบบ UI ในสไลด์ (กลุ่ม 43)

## เริ่มใช้งาน (3 คำสั่ง)

```bash
npm install
npm run setup      # สร้าง .env + ตารางฐานข้อมูล + ข้อมูลตัวอย่าง
npm run dev        # เปิด http://localhost:3000
```

👉 คู่มือละเอียดทีละขั้น (ติดตั้งโปรแกรม, เปิดใน VS Code, แก้ปัญหา, เปลี่ยนเป็น PostgreSQL): **[docs/GETTING-STARTED.md](docs/GETTING-STARTED.md)**

บัญชีทดสอบ (ชื่อผู้ใช้ = รหัสพนักงานหรืออีเมล เช่น `emp-0001@company.example` · รหัสผ่าน `1234` · หน้าเข้าสู่ระบบมีปุ่มเลือกบัญชีทดลองเมื่อ `SHOW_DEMO_ACCOUNTS="true"`): EMP-0001 พนักงาน · EMP-0003 พนักงานสัญญาจ้าง · EMP-0020 พนักงาน (ใช้ประกันส่วนเกินครบ 30 ครั้ง) · EMP-0010 HR · EMP-0011 หัวหน้า HR · EMP-0030 บัญชี · EMP-0050 ผู้ดูแลระบบ

## UI components (โครงสร้างแบบ shadcn/ui)

- `components.json` + `src/lib/utils.ts` (`cn`) + โฟลเดอร์ `src/components/ui/` — เพิ่มคอมโพเนนต์ด้วย `npx shadcn@latest add <ชื่อ>` ได้ทันที
- ดีไซน์โทน **warm cream + terracotta** (กรอบแอปมุมโค้งบนพื้นไล่สีพีช, sidebar สีครีม, หัวเพจตัวอักษร serif, ป้ายสถานะแบบเม็ดยามีจุดสี)
- ฟอนต์: **Noto Sans Thai Looped** (น้ำหนัก 400–700) ทั้งระบบ ติดตั้งผ่าน `@fontsource` — ไม่ต้องต่ออินเทอร์เน็ตตอน build
- ชื่อบริษัทแสดงจาก ตั้งค่าระบบ → ชื่อองค์กร (ค่าเริ่มต้น "บริษัท จัดการข้อมูลพนักงานและสวัสดิการ จำกัด")
- โทเค็นสีอยู่ใน `src/app/globals.css` (`@theme`): `brand-*` = terracotta, `ink-*` = สีเข้มโทนอุ่น และ **แทนที่ `zinc-*` ทั้งชุดด้วย neutral โทนครีม** — ทุกหน้าที่ใช้ `zinc-*` จึงเปลี่ยนโทนตามอัตโนมัติ; โทเค็นแบบ shadcn (`--background`, `--primary`, …) และธีมมืด `.dark` ยังใช้ได้
- `src/components/ui/index.tsx` — ปุ่ม การ์ด ฟอร์ม Modal Toast ที่ใช้ทั้งระบบ
- `src/components/AppShell.tsx` — โครงหน้าแอป: sidebar, แถบบน (breadcrumb, ค้นหาเมนู, โปรไฟล์), หัวเพจ + RBAC guard
- `src/app/login/page.tsx` — หน้าเข้าสู่ระบบ: แถบสีด้านบน + การ์ดฟอร์ม, **สลับภาษา TH / EN** (จำค่าไว้), เข้าสู่ระบบด้วย **รหัสพนักงานหรืออีเมล** + รหัสผ่าน, ตัวเลือก "จดจำรหัสพนักงาน"
  - หน้าเข้าสู่ระบบแสดงปุ่มบัญชีทดลองเฉพาะตอนพัฒนา (`SHOW_DEMO_ACCOUNTS`, ปิดอัตโนมัติใน production) — ระบบอ่าน role จากฐานข้อมูลแล้วพาไปหน้าแรกของบทบาทนั้นเอง
  - ระบบไม่เปิดให้สมัครเอง: HR/ผู้ดูแลระบบเป็นผู้สร้างบัญชี (ลิงก์ "ติดต่อฝ่าย HR" / "ลืมรหัสผ่าน?" แสดงคำแนะนำนี้)

## สถาปัตยกรรม (5 ชั้นตามสไลด์)

```
เบราว์เซอร์ (Presentation)          เซิร์ฟเวอร์ Next.js                            ฐานข้อมูล
┌──────────────────────┐  HTTPS   ┌──────────────────────────────────────┐   ┌──────────────┐
│ src/app/** หน้าจอ    │ ───────▶ │ /api/state  ข้อมูลตามสิทธิ์ (scope.ts) │   │ SQLite /     │
│ src/lib/client/api   │  cookie  │ /api/rpc    เรียก service (rpc.ts)     │──▶│ PostgreSQL   │
│ (ไม่มีข้อมูลลับ)       │ HttpOnly │ /api/files  ไฟล์แนบ → storage/uploads  │   │ (Prisma 7)   │
└──────────────────────┘          │ services/* ตรวจสิทธิ์ + กติกา + Audit │   └──────────────┘
                                  │ domain/rules.ts กติกาบริสุทธิ์           │
                                  └──────────────────────────────────────┘
```

- **Application Layer** `src/lib/domain/` — กติกา: วงเงิน 3 ระดับ, สิทธิ์ตามประเภทพนักงาน, วันจ่ายเงิน (ทดสอบแล้ว)
- **Service Layer** `src/lib/services/` — workflow ทุกขั้น ตรวจ RBAC (`assertCan`) + บันทึก Audit Log ก่อน–หลัง ในทุกการแก้ไข
- **Data Access Layer** `src/lib/server/` — `unitOfWork.ts` (transaction + คิวกันข้อมูลชน), `persist.ts` (แปลงตาราง ↔ โมเดล), `scope.ts` (ตัดข้อมูลตามสิทธิ์), `session.ts`, `files.ts`
- **Database Layer** `prisma/schema.prisma` — 16 ตาราง รวม `AuditLog` แบบ append-only

## ความปลอดภัยที่ทำแล้ว

- รหัสผ่านเก็บด้วย **scrypt + salt** · session เป็น **HttpOnly cookie ลงลายมือชื่อ HMAC** อายุ 8 ชม. — เปลี่ยนรหัสผ่านแล้ว session เก่าทุกเครื่องใช้ไม่ได้
- **RBAC ฝั่งเซิร์ฟเวอร์** ทุกคำสั่ง + ล็อกสิทธิ์ตาม Least Privilege (Admin อนุมัติไม่ได้, HR ตรวจคำขอตัวเองไม่ได้, บัญชีไม่เห็นข้อมูลพนักงาน)
- **ตัดข้อมูลตามบทบาท** ก่อนส่งถึงเบราว์เซอร์: พนักงานเห็นเฉพาะของตนเอง, HR เห็นคำขอทั้งหมด, บัญชีเห็นเฉพาะรหัสพนักงาน + เลขใบเสร็จ/ร้าน + ยอดเงิน (ไม่มีชื่อ เอกสาร หมายเหตุ — PDPA)
- ไฟล์แนบ: ตรวจชนิดจากเนื้อไฟล์จริง (magic bytes) จำกัด 5 MB, เปิดได้เฉพาะผู้มีสิทธิ์เห็นคำขอ, แนบไฟล์ของคนอื่นไม่ได้
- ป้องกัน CSRF (SameSite + ตรวจ Origin + บังคับ JSON), จำกัดการล็อกอินผิด 5 ครั้ง/15 นาที, security headers
- ทดสอบแล้ว 26 กรณีโจมตี/ข้ามสิทธิ์ผ่าน API จริง

## ขอบเขตที่ทำแล้ว (Functional Requirements)

5 บทบาท (พนักงาน / HR / หัวหน้า HR / บัญชี / ผู้ดูแลระบบ) · จัดการพนักงาน · แผนก / ตำแหน่ง 4 ระดับ / หัวหน้างาน · ประเภทสวัสดิการแบ่งหมวด · วงเงินตามระดับตำแหน่ง (มีวันที่มีผล ไม่ทับของเดิม) · ยื่นคำร้อง + เลขใบเสร็จ/ร้าน + แนบเอกสาร · คำนวณ "ขอเบิก → เบิกได้จริง" ทันที · เตือนใบเสร็จซ้ำ · HR อนุมัติ / ไม่อนุมัติ / ส่งกลับ (ต้องมีเหตุผล, อนุมัติของตัวเองไม่ได้) · กล่องยืนยันเลขคำขอ + ยอดเงินทุกปุ่มที่เกี่ยวกับเงิน · บัญชีบันทึกการจ่ายรายคำขอ (เงินสด/โอน/เช็ค) · คำขอแก้ไขผล/วงเงินแบบ Maker–Checker (หัวหน้า HR อนุมัติ) · รอบงบภัยพิบัติ · คำนวณวันจ่าย · แจ้งเตือนอีเมล · Audit Log (เฉพาะผู้ดูแลระบบ) · รายงานยอดเบิกต่อสวัสดิการ · Export CSV · สำรอง/กู้คืนข้อมูล

รายละเอียดกติกา, API และเรื่องที่ต้องยืนยันกับผู้ให้หัวข้อ: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)

## ข้อจำกัดที่ควรรู้

- อีเมลยังเป็นโหมดจำลอง (บันทึกลงตาราง `EmailMessage` ดูได้ที่ ผู้ดูแลระบบ → อีเมลแจ้งเตือน) — ต่อ SMTP ได้ที่ `sendEmail()`
- คิวกันข้อมูลชนทำงานในโปรเซสเดียว — ขยายหลายเซิร์ฟเวอร์ให้ใช้ PostgreSQL + advisory lock
- นอกขอบเขตตามสไลด์: โอนเงินอัตโนมัติ, Payroll/ภาษี, OCR ใบเสร็จ, Native app
