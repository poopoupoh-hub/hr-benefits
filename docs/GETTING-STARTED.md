# คู่มือเปิดโปรเจกต์

คู่มือนี้พาตั้งแต่เครื่องเปล่าจนเปิดระบบได้ ใช้ได้ทั้ง Windows และ macOS (ประมาณ 5–10 นาทีในครั้งแรก)
**ไม่ต้องติดตั้งฐานข้อมูล** — ระบบเก็บข้อมูลใน localStorage ของเบราว์เซอร์

---

## 0. สิ่งที่ต้องติดตั้งก่อน (ครั้งเดียว)

| โปรแกรม | ใช้ทำอะไร | ดาวน์โหลด |
|---|---|---|
| **Node.js รุ่น LTS (20, 22 หรือ 24)** | รันโปรเจกต์ (มี `npm` มาด้วย) | https://nodejs.org → ปุ่ม LTS |
| **Visual Studio Code** | เปิด/แก้ไขโค้ด | https://code.visualstudio.com |
| Git (ไม่บังคับ) | ทำงานร่วมกันเป็นทีม | https://git-scm.com |

```bash
node -v    # ควรได้ v20.x / v22.x / v24.x
npm -v
```

## 1. แตกไฟล์และเปิดใน VS Code

1. แตกไฟล์ zip วางไว้ที่ path สั้น ๆ ไม่มีช่องว่าง เช่น `C:\projects\hr-benefits` (เลี่ยงโฟลเดอร์ที่ซิงก์ OneDrive / iCloud)
2. VS Code → **File → Open Folder…** → เลือกโฟลเดอร์ที่มีไฟล์ `package.json` → **Yes, I trust the authors**
3. เปิด Terminal: **Terminal → New Terminal** (หรือ `` Ctrl + ` ``)

## 2. ติดตั้งแพ็กเกจและเปิดระบบ

```bash
npm install
npm run dev
```

รอจนขึ้น `Ready` แล้วเปิด **http://localhost:3000** — ครั้งแรกระบบสร้างข้อมูลตัวอย่างให้อัตโนมัติ

เข้าสู่ระบบด้วยรหัสพนักงาน (หรืออีเมล) + รหัสผ่าน `1234` — หรือกดเลือกบัญชีตัวอย่างใต้ฟอร์ม:

| รหัส | ชื่อ | บทบาท |
|---|---|---|
| EMP-0001 | สมชาย ใจดี | พนักงาน |
| EMP-0003 | ปิติ ขยัน | พนักงาน (สัญญาจ้าง) |
| EMP-0020 | ธนา หัวหน้า | พนักงาน (ระดับ 3 · ใช้ประกันส่วนเกินครบ 30 ครั้ง) |
| EMP-0010 | วิภา บุคคล | HR |
| EMP-0011 | ประภา หัวหน้าบุคคล | หัวหน้า HR |
| EMP-0030 | กมล บัญชี | บัญชี / การเงิน |
| EMP-0050 | ศิริ ผู้ดูแล | ผู้ดูแลระบบ |

## 3. ลองทั้ง Flow

| ขั้น | เข้าระบบด้วย | ทำอะไร |
|---|---|---|
| 1 | EMP-0001 สมชาย (พนักงาน) | ยื่นเบิก **ประกันส่วนเกิน** 1,500 บาท → ระบบแสดง "เบิกได้จริง 1,000" → แนบใบเสร็จ → ส่ง |
| 2 | EMP-0010 วิภา (HR) | เมนู **คำขอรอตรวจ** → เปิดคำขอ → ดูผลตรวจสิทธิ์อัตโนมัติ → **อนุมัติ** → กล่องยืนยันเลขคำขอ + ยอด (หรือ ส่งกลับแก้ไข / ไม่อนุมัติ พร้อมเหตุผล) |
| 3 | EMP-0030 กมล (บัญชี) | **รายการรอจ่าย** → บันทึกการจ่าย (เลือกวิธีจ่าย + เลขอ้างอิง/เลขเช็ค) → ยืนยัน |
| 4 | EMP-0050 ศิริ (ผู้ดูแลระบบ) | **Audit Log** → ค้นเลขคำขอ เห็นครบ ยื่น → อนุมัติ → บันทึกการจ่าย |

ลองเพิ่ม:
- **คำขอของ HR เอง:** วิภา (EMP-0010) มีคำขอรอตรวจ — ไม่ขึ้นในคิวของวิภา ต้องให้ประภา (EMP-0011) พิจารณา
- **คำขอแก้ไข (Maker–Checker):** EMP-0010 กด "ขอแก้ผล" ในคำขอที่ตัดสินแล้ว → EMP-0011 อนุมัติที่เมนู คำขอแก้ไข · ถ้าประภาส่งคำขอเองแล้วอนุมัติเอง ต้องใส่รหัสผ่านซ้ำ

> **สลับบทบาท:** ออกจากระบบแล้วเข้าด้วยบัญชีอื่นในเบราว์เซอร์เดิม — ทุกแท็บใช้ session เดียวกัน (เข้าระบบใหม่ = เปลี่ยนผู้ใช้ทุกแท็บ) · หน้าต่าง Incognito หรือเบราว์เซอร์อื่นจะมีข้อมูลแยกเป็นอีกชุด
> **ข้อมูลอยู่ในเบราว์เซอร์นี้เท่านั้น** คนละเครื่อง/คนละเบราว์เซอร์จะเห็นข้อมูลตัวอย่างชุดใหม่ของตัวเอง

**หยุดระบบ:** `Ctrl + C` · **ครั้งต่อไป** รันแค่ `npm run dev`

## 4. คำสั่งที่ใช้บ่อย

| คำสั่ง | ใช้ทำอะไร |
|---|---|
| `npm run dev` | รันโหมดพัฒนา (แก้โค้ดแล้วหน้าเว็บรีเฟรชเอง) |
| `npm run build` | build เป็น static site ในโฟลเดอร์ `out/` |
| `npm start` | เปิดผล build (`out/`) ที่ http://localhost:3000 |
| `npm test` | รัน unit test |
| `npm run lint` / `npm run typecheck` | ตรวจโค้ด |

## 5. นำขึ้นเว็บ (Deploy)

`npm run build` ได้โฟลเดอร์ `out/` เป็นไฟล์ HTML/CSS/JS ล้วน นำไปวางได้ทุกที่ที่เสิร์ฟไฟล์ static ได้: Netlify, Vercel, GitHub Pages, Cloudflare Pages, Nginx/Apache
- เว็บเซิร์ฟเวอร์ต้องเปิด clean URL (`/hr` → `hr.html`) — Netlify/Vercel ทำให้อัตโนมัติ · Nginx: `try_files $uri $uri.html $uri/ =404;`
- ผู้ใช้แต่ละคนจะมีข้อมูลของตัวเองในเบราว์เซอร์ของตน (ไม่มีข้อมูลกลาง)

## 6. ดู / ล้างข้อมูล

- ดูข้อมูล: เบราว์เซอร์ → DevTools (F12) → **Application → Local Storage → `hr-benefits:db`** · ไฟล์แนบอยู่ที่ **IndexedDB → `hr-benefits-files`**
- เริ่มข้อมูลใหม่: เข้าระบบด้วย EMP-0050 → ตั้งค่าระบบ → **รีเซ็ตข้อมูลเดโม** (หรือลบคีย์ `hr-benefits:db` ใน DevTools แล้วรีเฟรช)
- สำรอง/กู้คืน: EMP-0050 → ตั้งค่าระบบ → สำรองข้อมูล (ไฟล์ JSON) / กู้คืน

## 7. โครงสร้างโฟลเดอร์ — แก้อะไรที่ไหน

```
hr-benefits/
├─ src/
│  ├─ app/                    ← หน้าเว็บแต่ละหน้า (โฟลเดอร์ = URL)
│  │  ├─ (app)/me/            ← พนักงาน    (/me, /me/new, …)
│  │  ├─ (app)/hr/            ← HR — ตรวจและอนุมัติ (/hr), คำขอแก้ไข, วงเงิน, ข้อมูลหลัก
│  │  ├─ (app)/finance/       ← บัญชี
│  │  └─ (app)/admin/         ← ผู้ดูแลระบบ
│  ├─ components/             ← ชิ้นส่วนที่ใช้ซ้ำ (ClaimDetail = ปุ่มตามขั้นตอน, FlowGuide, ฟอร์มยื่นเบิก)
│  │  └─ ui/                  ← คอมโพเนนต์พื้นฐานแบบ shadcn
│  └─ lib/
│     ├─ domain/rules.ts      ← กติกาธุรกิจ: วงเงิน, สิทธิ์, วันจ่ายเงิน, ลำดับสถานะ
│     ├─ services/            ← workflow + ตรวจสิทธิ์ + Audit Log
│     │  ├─ claims.ts         ← ยื่น / HR อนุมัติ / จ่าย
│     │  └─ changes.ts        ← คำขอแก้ไข (Maker–Checker)
│     ├─ data/                ← db.ts (localStorage), files.ts (IndexedDB), session.ts, scope.ts, seed.ts
│     └─ client/api.ts        ← จุดที่หน้าจอเรียก service (แก้ที่นี่ถ้าจะต่อ Backend)
└─ docs/
```

**ตัวอย่าง:** เปลี่ยนลำดับสถานะ → `TRANSITIONS` ใน `src/lib/domain/rules.ts` · แก้กติกาวันจ่ายเงิน → `computePayDate` ใน `src/lib/domain/rules.ts` · แก้ข้อมูลตัวอย่าง → `src/lib/data/seed.ts` (แก้แล้วกดรีเซ็ตข้อมูลเดโม หรือเพิ่ม `DB_VERSION` ใน `constants.ts` ให้ทุกเครื่องเริ่มใหม่อัตโนมัติ)

## 8. แก้ปัญหาที่พบบ่อย

| อาการ | วิธีแก้ |
|---|---|
| `'npm' is not recognized` | ยังไม่ได้ติดตั้ง Node.js หรือยังไม่ได้ปิด-เปิด VS Code ใหม่ |
| Windows: `running scripts is disabled` | ใช้ Command Prompt แทน PowerShell หรือรัน `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| `Port 3000 is in use` | `npm run dev -- -p 3001` |
| ข้อมูลหายหลังเปิดใหม่ | เบราว์เซอร์ล้างข้อมูลเว็บไซต์ / ใช้โหมดไม่ระบุตัวตน — สำรอง JSON ไว้แล้วกู้คืน |
| "พื้นที่จัดเก็บของเบราว์เซอร์เต็ม" | สำรองข้อมูล แล้วรีเซ็ตข้อมูลเดโม (localStorage จำกัด ~5 MB) |
| เข้าสู่ระบบผิด 5 ครั้งแล้วโดนล็อก | รอ 15 นาที หรือรีเฟรชหน้า |
| เปิดไฟล์แนบของข้อมูลตัวอย่างไม่ได้ | ปกติ — ไฟล์ตัวอย่างมีแค่ชื่อ ไม่มีไฟล์จริง (ไฟล์ที่อัปโหลดเองเปิดได้) |
